农业 AI 决策可信性 · Decision Assurance

不是“能不能给答案”，而是“这个答案现在能不能进入真实生产”。

农业里的 AI、模型和农艺系统已经越来越会给答案。真正困难的是：当答案准备变成一次真实田间作业时，我们怎么知道它现在真的可以被采用？

GEOX 位于“答案”和“行动”之间。
它判断一个建议是否具备进入下一步生产流程的条件。关键证据缺失、过期或冲突时，系统会阻断或降级当前流程并说明原因；新的有效证据到达后，可以重新检查。

演示边界：下面把 GEOX 当前已经实现的“决策资格检查”和“人工审批—作业计划—执行记录—验收”能力组织成一个客户工作流。它展示当前软件能力，但不代表这两条能力线已经完成统一的无人值守生产级全链路验收。

03

一次完整的 GEOX 决策过程

GEOX 不替换客户现有系统；它把已有信息组织成可以检查、审批和追溯的决策过程。

系统边界：以下是组合客户流程演示。Temporal Decision Assurance 与 Commercial Control Loop 均有独立软件/工程证据，但当前不宣称它们已经在同一个真实客户现场完成统一 production qualification。

10:00｜数据进入

先检查输入能不能用于当前决策

田块、土壤状态、天气信息、最近灌溉记录、作物上下文进入系统。GEOX 检查 scope、时间可用性、质量、冲突和关键缺口。

10:01｜计算完成

建议候选：灌溉 20 mm

演示中发现关键天气证据超过当前允许窗口，且此时没有满足本次审批条件的合法替代证据，因此暂不进入审批。计算结果可以保留，但不能被包装成已经可执行的决定。

10:04｜新证据进入

重新检查，而不是自动“翻案”历史

新天气信息到达后，GEOX 对当前建议重新检查：田块正确、时间条件满足、关键证据已更新、没有阻断级冲突。新证据不会被倒填成 10:01 已知。

10:05｜当前状态

可以提交人工审核

当条件重新满足以后，GEOX 知道什么时候可以继续。这里的“继续”是进入人工审核，不等于自动执行。

10:08｜经理决定

灌溉决策

建议候选 20 mm 演示输入当前状态 可以提交人工审核主要依据 土壤状态 / 天气情况 / 最近灌溉记录 / 当前作物上下文

当前软件审批动作：

批准 · 拒绝 · 退回补充

APPROVE / REJECT / RETURN

责任边界

模型负责给出候选答案；人负责决定是否采用。GEOX 记录谁在什么时候，对哪个田块，依据哪一组当时可用的信息做了决定。

10:10｜进入作业流程

Approval → Operation Plan → 授权后创建 Action Task

审批通过以后，GEOX 可以先形成作业计划。只有在独立权限与执行条件满足后，后续流程才从已批准的作业计划创建执行任务。审批通过本身不会自动触发设备动作。

推荐集成方式

客户现有系统继续负责真实执行

GEOX 批准后的作业信息 → 客户灌溉系统 / FMIS / 人工流程 → 真实执行。设备直连需要项目级适配、权限、作用范围、故障安全和现场验收。

11:08｜执行回执返回

先确认“实际发生了什么”

演示：计划 20.0 mm，实际 18.7 mm；10:21 开始，11:08 结束，回执已收到。18.7 mm 与时间同样属于 Demo Input，不是客户生产记录。

11:09｜计划与实际比较

20.0 mm → 18.7 mm → 偏差 -1.3 mm

实际执行与计划不一致时，差异不会被隐藏，而是进入正式记录和后续验收上下文。

11:10｜验收记录

作业执行信息已记录；农业效果尚不能验证

执行回执 已收到计划与实际 已比较关键执行信息 已记录作业后效果证据 尚未获得
执行完成 ≠ 农业效果已经被证明。

新的土壤、作物或其他现场观测以后进入系统时，可以继续关联到这次作业；是否形成正式验收结论仍由 acceptance 层的证据规则决定。

05

客户真正买的是什么

不是“证据语义”这个词，而是更少的错误决策风险、更低的认知负担和更完整的责任链。

01｜少做一次不该做的操作

避免让过期、缺失或冲突的信息直接推动真实作业。

02｜少让管理者自己拼五个系统

先排除不能使用的信息，并把缺口与冲突暴露出来。

03｜决策更容易解释

记录为什么做、谁批准、用了什么、排除了什么，以及实际执行了什么。

04｜远程管理更可控

管理者可以沿着计划、批准、任务、回执、验收查看链路，而不是只听“已经处理好了”。

05｜争议后的证据

当一次农业作业后来出现问题，可以重新检查：当时究竟知道什么，以及为什么做出了那个决定。

06

GEOX 和现有系统是什么关系

不需要取代传感器、天气服务、FMIS、灌溉系统或农艺师。

现有系统继续做它们擅长的事

传感器告诉你测到了什么；天气服务告诉你可能发生什么；模型/AI 给出候选答案；FMIS 管理作业；控制系统执行设备动作；农艺师和经理承担专业判断与最终责任。

GEOX 工作在中间

它负责判断候选答案是否具备进入下一步的资格，组织人工审批，并在执行后记录“实际发生了什么”。

08

第一次使用 GEOX

不需要替换现有系统，建议从影子模式开始。

第一步

接入已有数据

CSV、现有 API、已有遥测、历史作业记录。

第二步

旁路运行

不控制设备，只记录哪些建议可以继续、哪些应该暂停，以及为什么。

第三步

与真实决策比较

统计阻断、降级和人工决策变化，并记录对应的经营风险。

第四步

形成客户自己的价值证明

回答 GEOX 到底发现了多少真正会改变农业操作的问题，以及这些问题对客户值多少钱。

Pilot 边界：这里的“影子模式”是建议部署方式，不宣称一个通用的 Shadow Mode 产品开关；价值证明必须使用客户自己的作业数据和成本数据。
